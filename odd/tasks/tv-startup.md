# Android TV startup
Show the boot splash for the whole Apple Music load and remove the sluggish first seconds after a cold start.
Branch feat/tv-startup from main 81e95c4; delivery as a PR and a later TV release.

## Specs
1. S1 — User: "esta parte de espera, debe mostrar el booting de cuando esta iniciando la app, no esta parte" (screenshot: only "nu11signal: loading Apple Music, this can take a minute on a TV..." on a black terminal).
2. S2 — User: "cuando se inicia la app luego de cerrarla completamente, dura varios segundos muy lenta que no responde, luego ya es bastante fluida".
3. S3 — User chose to accept the Android installer's final "Se instaló la app" screen with the generic icon ("Aceptarla tal cual"); no change to the installer mechanism.
4. S4 — User chose "Mantener la animación hasta que esté fluida" for the remaining slowness: keep the boot splash until Apple Music's page frees the shared WebView renderer thread, so the UI appears already responsive.

Fix: Runtime.Sized() closes on the first valid resize; playAndroidTV starts the program after it (bounded by androidSizeWait, 5 s). RED: sized_test.go did not compile (Sized undefined); GREEN: TestSizedClosesOnTheFirstValidSize, go test -race ./cmd/nu11signal ./internal/androidtv ./internal/radio 1050 passed; go vet passes, including GOOS=linux CGO_ENABLED=0 for internal/androidtv. The linux-only TestResizeNotifiesTUI builds a Runtime without the channel, so the close is nil-guarded.
- L7: Native review review-7ee99bf1edf30919 (resilience, reliability) over 6d914c7..84da32f approved and acknowledged. The independent verifier then traced a shutdown race: Bubble Tea's default SIGINT/SIGTERM handler sends its quit message unconditionally, while signal.NotifyContext in playAndroidTV also cancels ctx; if ctx ends the event loop first, the handler blocks and Run never returns (pre-existing for the old UI program, now covering startup too). Fix: tea.WithoutSignalHandler() on the program, ctx owns the signals. No deterministic RED: it needs a real OS signal racing the cancellation; go vet and go test -race ./cmd/nu11signal ./internal/radio (1020) pass. An early startup Run error does not cancel ctx; the player load stays bounded (2 minutes).
